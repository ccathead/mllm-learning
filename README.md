# MLLM 实践学习

通过 **跑通开源项目 → 跟踪源码 → 做一个受控改动 → 评测 → 记录结论** 学习多模态大模型。

目标：理解图像如何进入语言模型、训练 loss 如何计算，并完成一个可评测、可微调的图像理解应用。已有 Python / PyTorch / Transformer 基础；本地 Windows 管理代码与笔记，云端 Linux GPU 运行推理和训练。

## 六周计划

每周约 8–12 小时，按验收推进，时间可调整。贯穿任务暂定为 **商品图片属性提取**：输出类别、颜色、可见文字；无法判断时返回“无法确定”。

| 周次 | 开源项目与实践 | 验收产物 |
|---|---|---|
| 1 | LLaVA：单图推理 → 批量推理；收集 30 张图并人工标注 | 推理入口、基线报告、10 个失败案例 |
| 2 | LLaVA：跟踪预处理、视觉编码器、投影层、LLM；MiniGPT-4：对比连接方式 | 带实际张量形状的数据流图、关键函数与 commit |
| 3 | Qwen2.5-VL：复用同一评测集；比较基础提示词、优化提示词、裁剪策略 | 模型与策略对比报告、应用原型 |
| 4 | 拆解数据处理、聊天模板、labels 与冻结策略；20–50 条样本过拟合检查 | 样本检查、梯度检查、训练流程记录 |
| 5 | 整理约 500–2,000 条领域指令数据并做 LoRA；按商品/来源划分数据 | 未见数据上的微调对比、通用能力检查 |
| 6 | 封装交互界面或 API，加入 JSON 校验、失败重试和批量处理 | 可演示应用、复现说明 |

视频与 Agent 放在六周主线完成之后。数据数量是教学起点，实际效果待实验验证。

## 从这里开始

1. 阅读 [第一周任务](docs/first-week.md)，跑通一张图片。
2. 从 [源码拆解模板](templates/source-analysis.md) 建立笔记。
3. 每次实验复制 [实验模板](templates/experiment.md)，将报告放到 `experiments/`。
4. 将结论、卡点和下一步同步到 [项目进度](index.md)。

## 仓库布局

- `docs/`：起步任务、工作流、官方资料。
- `notes/`：源码拆解与概念笔记。
- `src/`：自己编写的推理、评测、应用代码。
- `configs/`：推理与训练配置。
- `experiments/`：实验报告和小型汇总指标。
- `examples/`：有权分享的少量示例素材。
- `templates/`：源码、论文和实验记录模板。
- `data/`、`checkpoints/`、`outputs/`、`external/`：本地或云端使用，忽略提交。

各项目使用独立环境，依赖按官方说明安装，首次跑通后保存环境版本。尚未验证环境前，不提供统一的依赖锁定文件。

## 项目分工

- [LLaVA](https://github.com/haotian-liu/LLaVA)：推理和架构拆解；HF 模型与原生源码实现需分别记录。
- [MiniGPT-4](https://github.com/Vision-CAIR/MiniGPT-4)：连接模块和训练阶段对比；先读源码，按需要运行。
- [Qwen2.5-VL 模型卡](https://huggingface.co/Qwen/Qwen2.5-VL-3B-Instruct)：应用与领域微调。

官方资料及版本注意事项见 [sources.md](docs/sources.md)。所有结果必须能回到代码、配置、数据版本或日志；尚未验证的信息标注“待核验”。
